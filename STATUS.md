# Status

Short note for weekly check-ins. Agents should update this when something ships.

## What shipped

- The product is now **Hope's Voice**. The public repo is [davidgeorgehope/hopes-voice](https://github.com/davidgeorgehope/hopes-voice) (the previous repo URL redirects here), MIT-licensed, with the existing SwiftUI iPad app and the FastAPI backend (no secrets, no family data, no screenshots).
- Home-screen display name and user-facing copy say Hope's Voice. The iOS bundle ID is `com.davidgeorgehope.hopesvoice` (tests: `com.davidgeorgehope.hopesvoice.tests`).
- Production API host is [hopesvoice.davidgeorgehope.com](https://hopesvoice.davidgeorgehope.com), configured in the app as the single constant `APIClient.productionBaseURL`. Apps never hold an xAI key; the backend generates original PECS pictures and spoken audio through the xAI API (Grok models only).
- Card pictures now fill their cells. The app trims near-white margins at render time; the backend does the same (and re-pads to a ~6% margin) on newly generated cards, and the generation prompt asks for the subject to fill ~85% of the frame. A one-off script `backend/scripts/retrim_card_images.py` can re-process existing images in the data dir after backing up originals.
- iPhone layout no longer clips: the message bar, core-words row, and board grid all fit the screen width (including a 4-column grid). The sentence bar keeps a usable chip well between Speak, Back, and Clear.
- iPhone fit fix: the board width is now measured from the window, not from the board's own content. Before, one row wider than a phone (the caregiver profile switcher) widened the whole screen, the fixed-width rows then measured even wider, and after locking back to kid mode the message bar, core row, and buttons stayed cut off on both edges. Cells now get an exact width from the column count, the default board fills the height (rows share the space below the core row and only scroll when there are more rows than seats), empty seats are invisible in kid mode, one-word labels shrink instead of breaking mid-word, and the caregiver row scrolls sideways on a phone. Removing an imported board now brings the default board, grid size, and message bar back right away. `LayoutFitUITests` asserts that every cell, core word, and message-bar control stays inside the screen on the default board, a folder, caregiver mode then Lock, portrait → landscape → portrait, and the imported sample; it was run on iPhone SE (3rd gen), iPhone 16 Pro, iPhone 16 Pro Max, and iPad mini (A17 Pro) simulators. Launch with `-ClearImportedBoard` to start a simulator from the default board's Home.
- iPad app features already in the tree: message bar (speak / clear / backspace), kid vs caregiver mode, folders, edit/hide, offline speech from cache, sticky core words (I / want / more / help / stop / go), multiple child profiles (defaults: Child 1 / Child 2), reorder/rename, recents, caregiver search, and caregiver voice-add via on-device speech recognition.
- Proloquo2Go-familiar editing is in the app (layout and interaction only, original assets). A low-contrast toolbar Edit control unlocks after a 1.5s press or a two-finger hold (the title long-press still works). Done returns to kid mode. In Edit, tap a button for the button editor (label, spoken text, Generate with AI / choose an on-device photo / keep, colors, word vs folder, Save / Cancel, Hide / Delete). Tap an empty cell or “+ Add button” to place a new button at that coordinate. The board is a fixed row × column grid (default 4×6 on iPad, 3×4 on iPhone, 2…8 configurable); empty cells stay visible in Edit and hidden cards keep their seats, so neighbors do not slide. Tapping the message bar speaks the sentence. Per-profile toggles cover speak-on-tap, tap-bar-to-speak, and clear-after-speak.
- Caregivers can import a `bestwishes.board/v1` file (or a folder that contains one) from Edit → Settings. Validation is all-or-nothing (unique ids, no overlapping positions, every folder target exists, every cell fits its grid); unknown fields are preserved. A public synthetic fixture is in `ios/BestWishes/BestWishesTests/Fixtures/sample.board.json` and `backend/tests/fixtures/sample.board.json`. The same checks are available from `backend/scripts/validate_board.py`. An imported board stays on the device for that profile and is not uploaded to the public server board.
- Settings needed by an imported board are editable and persist per profile: background color, border-only / fill / as-written color mode, visible rows and columns, show core row and recents, message-bar style (including a compact blue bar with a picture under each word and a delete-last control), return Home after a word is picked in a folder, add a folder button's word to the message bar, and voice engine / rate / pitch (iOS Samantha or the server Eve voice as stand-ins at about 180 wpm). Launch the simulator with `-ImportBoard /path` to load a file outside git.
- Docs: mission and requirements (including the Proloquo2Go-familiar editor workflow), API contract, USB device-run notes, board import format (`bestwishes.board/v1`), contributing guide, store listing copy, and a maintenance-loop skill.
- Product stack is decided: keep SwiftUI for iPhone + iPad; build Android separately in Kotlin + Jetpack Compose against the same API.
- GitHub Actions CI runs on `main` for [backend](https://github.com/davidgeorgehope/hopes-voice/actions/workflows/backend.yml) (`pytest`, xAI mocked) and [ios](https://github.com/davidgeorgehope/hopes-voice/actions/workflows/ios.yml) (Xcode, iPad (A16) simulator, `CODE_SIGNING_ALLOWED=NO`). Badges are on the README. The Xcode project, target, and scheme remain `BestWishes` so CI and the Mac mini auto-push script stay wired.
- Fitzgerald-key colors ([#7](https://github.com/davidgeorgehope/hopes-voice/issues/7)): word buttons on the default board and in the core row are filled by part of speech: people and pronouns yellow, actions green, describing words blue, things orange-yellow, social pink, questions purple, little words lavender, and no/not red. These are our own fills on our own cells. A built-in word list covers core words, and unknown words count as things. New profiles start with it on. Edit → Settings → Color by word type turns it off, `profile.colors` overrides any class, and a color a caregiver picks for a button always wins. Imports with `"colorScheme": "fitzgerald"` color each cell by its `pos` (or a guess from its label) unless the cell sets `bg`. Imports with `custom` (like the first family's board) are unchanged. Tests: `WordClassTests`.
- New picture on an existing button: in Edit, open a word button, tap **New picture**, then Save. The server makes a new original picture for that word (`POST /v1/cards/{slug}/image`, audio kept, the old picture saved as `image.prev.png`), the app drops its copy, including an on-device photo, downloads the new one, and the cell redraws right away. To keep the xAI spend capped, one word can be redone at most every 20 s and the server allows 40 redos a day (`HOPESVOICE_REGEN_COOLDOWN_SECONDS`, `HOPESVOICE_REGEN_DAILY_CAP`). If the server refuses, the old picture stays and the editor shows why. Imported boards keep their own pictures. Tests: `backend/tests/test_regenerate_image.py`, `RegeneratePictureTests`.
- Backup and restore of the whole vocabulary: Edit → Settings → Backup → **Save a backup of everything…** writes one `hopesvoice.backup/v1` JSON file (to Files, iCloud Drive, AirDrop). It holds both profiles' imported boards, hide / order / label / position / spoken-text / color edits, settings, message bar, grid size and recents, plus every on-device photo a board still uses. **Restore from a backup…** checks the whole file first (format, every picture's hash, the board's validity), asks to confirm, then replaces this device's state. A bad file changes nothing. Words on the server are not copied; the server keeps them. Launch hooks: `-ExportBackup <path>`, `-RestoreBackup <path>`. Tests: `VocabularyBackupTests`, `BackupUITests`, and public fixtures `sample.backup.json` / `empty.backup.json`.
- Fix for [#28](https://github.com/davidgeorgehope/hopes-voice/issues/28): the toolbar Edit lock now uses SwiftUI's own long press (the same path as the title long-press), shows press feedback, fires a haptic when the hold completes, and enters Edit immediately. The two-finger hold stays on a UIKit recognizer that hands off to the main queue. A new `BestWishesUITests` target holds XCUITests for hold → Done, repeat holds, short tap, and a screenshot check that the screen really changes with no navigation in between.
- Fix for [#27](https://github.com/davidgeorgehope/hopes-voice/issues/27) (slow app): everything from the server is now cached on the device and the UI never waits on the network. Boards and pictures live on disk; decoded, trimmed thumbnails (about 2x the largest cell) live in an in-memory `ThumbnailCache` with a small disk copy, so cells draw from memory and decode happens off the main thread. The board refetches with `If-None-Match` and the server answers `304` when nothing changed (the backend now sends an `ETag` on `/v1/board` and `/v1/cards`; asset files already had `ETag`/`Last-Modified`). Pictures are revalidated at most once per launch and only re-downloaded when they changed. The first tap after launch no longer waits for the audio session (it is warmed in the background and audio starts on its own queue). Measured with `PerformanceTests` on a 500-card board with 1024 px pictures (iPhone 16 Pro simulator, Release build): board on screen from cold 130 ms to 22 ms, picture lookup for the whole board 175 ms to 16 ms, the tap call on the first tap 124 ms to 0.8 ms, steady tap to visible feedback 22 ms to 15 ms (budget 100 ms). Debug build, same board: cold render 1993 ms to 55 ms. The budgets (tap under 100 ms, cold render under 600 ms, lookup under 150 ms) are asserted on the Mac mini simulators before merge. CI runs them too and prints the PERF numbers, but only warns on a miss, because hosted macOS runners vary by up to 1000x run to run (the same commit measured the first tap at 2.4 ms and 2229 ms).
- Recents row ([#27](https://github.com/davidgeorgehope/hopes-voice/issues/27) follow-up): it used to hold up to 8 words in a horizontal scroller, so it ran off the right edge of a phone, and it repeated core-row words (I, want, ...). It never grew without bound (it was capped at 8 and de-duplicated when written), but the cap was not applied when read back. Now Recents holds at most 6 words, one row of the same fixed cells as the core row, so it never scrolls. It is de-duplicated, never contains a core-row word, is trimmed the same way when loaded from disk (older files with 8 entries are cut to 6), and survives relaunch. Edit → Settings → Show recents turns it off, and imported Proloquo2Go boards start with it off. Tests assert the cap, de-duplication, core exclusion, relaunch, and the import default.

- Closes [#1](https://github.com/davidgeorgehope/hopes-voice/issues/1) (configurable settings). Edit → Settings now has a Profile name field: a caregiver can rename each profile on this device (defaults stay Child 1 / Child 2, blank resets, up to 24 characters), and the profile switcher shows the name. Child 1 / Child 2 remain the identity for launch arguments, accessibility identifiers, and saved keys. The Settings sheet now opens with the board's real rows × columns and Save applies both (before, it could show the 6-column import default on a 4-column board and save 6 columns). A new `SettingsPersistenceTests` suite proves that grid size, background color, color mode, core row / recents, message-bar style and toggles, folder behavior, voice engine / rate / pitch, and profile names survive a relaunch and stay separate per profile, and that an imported board's per-board rows / columns survive a relaunch.

## What's next

- Performance: the iPad auto-push builds Debug, which is several times slower than Release for Swift. Switching `bestwishes-autopush.sh` to `-configuration Release` would make the family's iPad feel faster still (not changed here, it is outside the repo).
- Settings follow-ups: a caregiver control to set a size for one folder on the default (non-imported) board; today per-board sizes come from an imported board file.
- Remaining Proloquo2Go-familiar polish: Folder buttons use a tab silhouette, short folders keep empty rows so cells on the last rows sit at the bottom, and the kid-mode Edit control no longer shows on-screen hint text. See issue #3, and `docs/REQUIREMENTS.md`.
- Finish recreating the first family's existing setup from the *private* import file (held outside this repo): generate original pictures for the remaining stock-symbol cells (after owner approval of the remaining batch), and close any layout differences found in side-by-side screenshots.
- An Android app scaffold and an Android CI build job once the Kotlin/Compose scaffold exists.
- Store-readiness work for a free App Store and Google Play listing (privacy policy, COPPA / kid-safe handling, accessibility, signing). Paid fees need owner approval.
